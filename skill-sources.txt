# Skill sources for the GO AI hub (read by go-jupyter-link-skills; see scripts/README.md).
#
# One source per line:  <git url>  <ref>  <subdirectory holding <skill>/SKILL.md dirs>  [options]
#   options: sparse=<dir>[,<dir>]  blobless clone limited to these directories (+ the
#                                  skills subdirectory; root files come along)
#            exclude=<skill>[,..]  skills of this source not to link into ~/.claude/skills
#                                  (they remain in the checkout, so a session started
#                                  inside a workspace clone still sees them as
#                                  project skills)
#            workspace             also give each user a clone of the repository in
#                                  the home (~/<repo name>) as their editing surface
#                                  for the repository itself; skills still link to
#                                  the store, never into that clone
# Name collisions between sources: the source listed first wins, also when the later
# source had the name first.
#
# Each source is checked out once on the box, root-owned, under
# /var/lib/go-jupyter/skill-sources/<repo name> (the store), and every seeded
# account gets a symlink ~/.claude/skills/<skill> -> the store, for every skill the
# source holds. Everything for everyone: there is no per-template list (kltm,
# 2026-09-28). Nobody edits the store; a skill changes by a pull request to its
# repository, and the merge is in every home within minutes (kltm, 2026-10-14, #87;
# until then each home had its own editable clone). A curator's own skill, a real
# directory in ~/.claude/skills under a name no source provides, is left alone.

# installed. Remove the stand-ins when the toolchain arrives.
